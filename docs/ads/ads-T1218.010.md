# Alerting and Detection Strategy (ADS) — Rule 100008

## Goal

Detect Regsvr32 proxy execution of a COM scriptlet (T1218.010, known as Squiblydoo). regsvr32.exe loads scrobj.dll to run a .sct script, which executes the adversary's code through a signed Microsoft binary and can pull the scriptlet from a remote URL.

## Categorization

- **ATT&CK technique(s):** `T1218.010` — System Binary Proxy Execution: Regsvr32
- **Tactic(s) (v20):** Stealth
- **Lab rule_id:** `100008`
- **Source Sigma rule:** `rules/sigma/T1218.010_regsvr32_scrobj.yml` (original, written for this lab)

## Strategy Abstract

Keys on Sysmon Event 7 (image load) where the loading process is regsvr32.exe and the loaded image is scrobj.dll. Normal DLL registration with regsvr32 does not load scrobj.dll, so the pair is the signal, whatever the command line says.

## Technical Context

Chains on 61609 (Sysmon Event 7). Fields used are `win.eventdata.image` and `win.eventdata.imageLoaded`. The rule only works because the sysmon-modular config logs this image load. Many Sysmon configs drop most Event 7 volume, and with image-load logging off for scrobj.dll this rule is blind.

```xml
<!-- Rule 100008 - Regsvr32 COM scriptlet execution (scrobj.dll image load) -->
<!-- MITRE ATT&CK: T1218.010 - System Binary Proxy Execution: Regsvr32 -->
<!-- Sysmon Event ID 7 - Image Loaded -->
<!-- Converted from rules/sigma/T1218.010_regsvr32_scrobj.yml with sigma_to_wazuh, then manual fixes (see ADS). -->
<rule id="100008" level="8">
  <if_sid>61609</if_sid>
  <field name="win.eventdata.image" type="pcre2">(?i)\\regsvr32\.exe$</field>
  <field name="win.eventdata.imageLoaded" type="pcre2">(?i)\\scrobj\.dll$</field>
  <description>T1218.010: Regsvr32 COM scriptlet execution - $(win.eventdata.image) loaded $(win.eventdata.imageLoaded)</description>
  <mitre>
    <id>T1218.010</id>
  </mitre>
</rule>
```

## Blind Spots and Assumptions

A renamed copy of regsvr32.exe evades, because the rule matches the Image path and not the PE OriginalFileName (`REGSVR32.EXE`). Scriptlets run through other hosts (rundll32, mshta, cscript) are out of scope by design. With no Event 7 there is no detection, so an Event 1 sibling on the regsvr32 command line (`/i:` together with scrobj.dll) would be a useful fallback. Not written or measured here.

## False Positives

Benign COM scriptlet registration is rare on workstations, though legacy installers and some management tooling use it. The baseline runs no regsvr32 activity, so the FP cost of 0 across 5 runs (pass 0) is expected and does not test the rule against benign scriptlet use.

## Validation

- **Positive test:** Atomic T1218.010 #1 "Regsvr32 local COM scriptlet execution" (GUID 449aa403-6aba-47ce-8a37-247d21ef0306): `C:\Windows\system32\regsvr32.exe /s /u /i:"<atomics>\T1218.010\src\RegSvr32.sct" scrobj.dll` from the command_prompt executor.\
&emsp;*Result:* **Detected**, 3 lab runs, on Event 7.\
&emsp;*Latency (Sysmon event `systemTime` minus run start):* **0.677 s / 0.792 s / 0.679 s.**

- **Converter fidelity:** sigma_to_wazuh converted it (`rules/wazuh/T1218.010_sigma_to_wazuh.xml`).\
&emsp;*Manual fixes:* if_sid scoped to 61609 (Event 7) instead of the generic Windows list, both `endswith` matches anchored with `$`, and MITRE IDs.\
&emsp;*Lab conventions:* rule ID, level 13 to 8.

- **Built-in comparison:** the stock run fired only 92032 (level 3, T1087/T1059.003) on Event 1 because the atomic ran under cmd.exe, a generic hit. No stock rule fired on the Event 7 scrobj.dll load. In the lab runs 92032 still fired separately on Event 1 and 100008 alerted on Event 7.
- **Negative test:** FP cost 0 across 5 baseline runs (pass 0), precision 1.0.

## Priority

Suggested alert level: ***8***

## Response

*Analyst Action:* Pull the regsvr32 command line from the matching Event 1, find the .sct path or URL, retrieve and review the scriptlet, and check for child processes and network connections from regsvr32.exe.
