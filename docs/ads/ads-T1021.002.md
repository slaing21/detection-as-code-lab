# Alerting and Detection Strategy (ADS) — Rule 100012

## Goal

Detect mapping of a Windows admin share (C$, ADMIN$, IPC$) with `net use` (T1021.002). With valid credentials, an adversary maps a remote host's admin share to move laterally, copy tools, or set up remote execution.

## Categorization

- **ATT&CK technique(s):** `T1021.002` — Remote Services: SMB/Windows Admin Shares
- **Tactic(s) (v20):** Lateral Movement
- **Lab rule_id:** `100012`
- **Source Sigma rule:** `rules/sigma/T1021.002_net_use_admin_share.yml` (original, written for this lab)

## Strategy Abstract

Keys on Sysmon Event 1 where the image is net.exe or net1.exe, the command line contains use as a whole word, and it names an admin share (C$, ADMIN$, or IPC$). It keys on the command, not on the SMB connection.

## Technical Context

Hand written because sigma_to_wazuh skips multi-selection conditions. Chains on 61603. Both commandLine fields must match. net use does not start net1.exe, so the rule fires once per command. The atomic maps `\\Target\C$`, a name that does not resolve in the isolated lab, so no SMB connection happened and no Event 3 was logged. The rule does not depend on one.

```xml
<!-- Rule 100012 - Admin share mapping via net use (net.exe/net1.exe) -->
<!-- MITRE ATT&CK: T1021.002 - Remote Services: SMB/Windows Admin Shares -->
<!-- Sysmon Event ID 1 - Process Creation -->
<!-- Hand written from rules/sigma/T1021.002_net_use_admin_share.yml (sigma_to_wazuh skips multi-selection conditions). -->
<rule id="100012" level="8">
  <if_sid>61603</if_sid>
  <field name="win.eventdata.image" type="pcre2">(?i)\\net1?\.exe$</field>
  <field name="win.eventdata.commandLine" type="pcre2">(?i)\buse\b</field>
  <field name="win.eventdata.commandLine" type="pcre2">(?i)(C|ADMIN|IPC)\$</field>
  <description>T1021.002: Admin share mapping - $(win.eventdata.commandLine)</description>
  <mitre>
    <id>T1021.002</id>
  </mitre>
</rule>
```

## Blind Spots and Assumptions

Keys on net.exe and net1.exe. Mapping with PowerShell (`New-PSDrive`, `New-SmbMapping`), copying through a UNC path directly, or browsing with Explorer evades. Other drive shares (D$, E$) are not matched. The share pattern is unanchored, so any share name ending in C$ (for example PUBLIC$) also matches. The rule sees the command, not the connection, so it cannot tell whether the mapping succeeded. SMB traffic (Event 3 to port 445) was never observed in this lab, so a network-based rule was not tested.

## False Positives

Admins map admin shares for maintenance. The baseline maps and unmaps `\\127.0.0.1\C$` (manifest actions `map-admin-share` and `unmap-admin-share`), and both commands match, so the rule raised 2 alerts per baseline run: FP cost 10 across 5 runs in both passes, precision 0.231.

## Tuning Decision

Tuning was not applied. Two filters were considered. Excluding `/delete` is principled, since disconnecting a share is not lateral movement, and it would halve the FP cost (10 to 5), but the map command still matches, so the score would stay at 2. Excluding the loopback target would pass this baseline only because the single-host lab maps 127.0.0.1 as a stand-in for an admin mapping a remote share, so it would game the baseline. The atomic also passes explicit credentials (`/u:`), but admin scripts do the same, so that is not a safe discriminator either. Admin share mapping is not separable from benign administration at the single-event level, so the rule stays at coverage 2 and the FP cost is reported as the finding. The `/delete` exclusion is recorded as a candidate for a future pass.

## Validation

- **Positive test:** Atomic T1021.002 #1 "Map admin share" (GUID 3386975b-367a-4fbb-9d77-4dcf3639ffd3): `cmd.exe /c "net use \\Target\C$ P@ssw0rd1 /u:DOMAIN\Administrator"` with the default inputs.\
&emsp;*Result:* **Detected**, 3 lab runs, one alert per run.\
&emsp;*Latency (Sysmon event `systemTime` minus run start):* **0.592 s / 0.651 s / 0.657 s.**

- **Converter fidelity:** Not converted (multi-selection condition). Written by hand from the Sigma logic and confirmed live with the atomic.
- **Built-in comparison:** the stock run fired only 92036 (net.exe started by a cmd shell, mapped to T1059.003/T1574.001), a generic hit. No stock rule maps admin share use to T1021.002. In the lab runs 100012 outranked 92036 at level 8.
- **Negative test:** FP cost 10 across 5 baseline runs (2 per run), the same in both passes.

## Priority

Suggested alert level: ***8***

## Response

*Analyst Action:* Identify the target host and the account. A mapping to another workstation's admin share, from a non-admin account, or followed by file copies or remote execution is escalated. The command line can contain a plaintext password (the atomic's does), so treat the alert as sensitive and rotate the credential if it is real.
