# Alerting and Detection Strategy (ADS) — Rule 100013

## Goal

Detect certutil.exe used as a downloader (T1105 Ingress Tool Transfer). `certutil -urlcache -f <url> <file>` pulls a file from a remote server with a signed Microsoft binary, a common way to stage tools after initial access.

## Categorization

- **ATT&CK technique(s):** `T1105` — Ingress Tool Transfer
- **Tactic(s) (v20):** Command and Control
- **Lab rule_id:** `100013`
- **Source Sigma rule:** `rules/sigma/T1105_certutil_urlcache.yml` (original, written for this lab)

## Strategy Abstract

Keys on Sysmon Event 1 where OriginalFileName is certutil.exe and the command line contains urlcache. Matching the PE name also catches a renamed certutil. It keys on the command, not on the network connection or the written file.

## Technical Context

Hand written because sigma_to_wazuh skips multi-selection conditions. Chains on 61603. Only Event 1 was observed. There was no Event 3 (the sysmon-modular network filtering did not log certutil's connection), no Event 22 (the target was an IP address, so no DNS query), and no Event 11 (the server returned 404, so no file was written). A rule on any of those events would not have fired in this lab.

```xml
<!-- Rule 100013 - Certutil URL download (urlcache) -->
<!-- MITRE ATT&CK: T1105 - Ingress Tool Transfer -->
<!-- Sysmon Event ID 1 - Process Creation -->
<!-- Hand written from rules/sigma/T1105_certutil_urlcache.yml (sigma_to_wazuh skips multi-selection conditions). -->
<rule id="100013" level="8">
  <if_sid>61603</if_sid>
  <field name="win.eventdata.originalFileName" type="pcre2">(?i)^certutil\.exe$</field>
  <field name="win.eventdata.commandLine" type="pcre2">(?i)urlcache</field>
  <description>T1105: Certutil URL download - $(win.eventdata.commandLine)</description>
  <mitre>
    <id>T1105</id>
  </mitre>
</rule>
```

## Blind Spots and Assumptions

Other download tools evade: bitsadmin, PowerShell `Invoke-WebRequest`, curl.exe, and certutil switches other than urlcache that can also download (such as `-verifyctl`). Detection rests on the command line alone. In this lab certutil's network connection was not logged, so a variant that keeps the URL off the command line would leave no other evidence in Sysmon.

## False Positives

Legitimate certutil URL downloads are rare on workstations. The baseline's download uses `Invoke-WebRequest` (manifest action `download-local-file`), not certutil, so the FP cost of 0 across 5 runs (pass 0) does not test the rule against benign certutil use.

## Validation

- **Positive test:** Atomic T1105 (GUID dd3b61dd-7bbc-48cd-ab51-49ad1a776df0) "certutil download (urlcache)": `cmd /c certutil -urlcache -split -f <remote_file> <local_path>`, with remote_file pointed at the SIEM VM's local HTTP server, which returned 404.\
&emsp;*Result:* **Detected**, 3 lab runs.\
&emsp;*Latency (Sysmon event `systemTime` minus run start):* **0.859 s / 0.846 s / 0.684 s.**

- **Environment changes:** Microsoft Defender RTP needed to be disabled first for the rule to be tested. For the atomic test to run offline, the file was pointed against the local HTTP server.
- **Converter fidelity:** Not converted (multi-selection condition). Written by hand and confirmed live with the atomic.
- **Built-in comparison:** the stock run fired only 92032 (level 3, T1087/T1059.003) on the cmd launcher, a generic hit. No stock rule is certutil-specific or maps to T1105. In the lab runs 100013 outranked 92032 at level 8.
- **Negative test:** FP cost 0 across 5 baseline runs (pass 0), precision 1.0.

## Priority

Suggested alert level: ***8***

## Response

*Analyst Action:* Pull the URL and output path from the command line, retrieve and hash the file if it was written, check the URL and host reputation, and clear the cached copy (`certutil -urlcache * delete`).
